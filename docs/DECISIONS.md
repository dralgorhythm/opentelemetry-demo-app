# Decisions

Every real fork in the road, as a numbered row: what's active, what it beat,
and what flipping it costs. The switch location is where the change starts —
most carry a comment at that exact spot. Deliberately-not-done work lives in
[DEFERRED.md](./DEFERRED.md).

| # | Decision | Active choice | Alternative(s) | Trade-off / switch path |
|---|----------|---------------|----------------|-------------------------|
| 1 | **Where the infra lives** | monorepo — Terraform, chart, workflows in the app repo | separate infra repo | one PR series tells the whole story and app+infra changes land atomically; splits later along the `terraform/` seam |
| 2 | **Terraform layout** | directories: `bootstrap` / `shared` / `envs/<env>` roots × one `modules/stack`, uniform state keys `otel-demo-app/{bootstrap,shared,envs/<env>}.tfstate` | workspaces · one flat root | per-stack state = per-stack locks, blast radius, and IAM walls (the boundaries deny foreign keys); workspaces share one backend surface |
| 3 | **State locking** | S3-native `use_lockfile = true` | DynamoDB lock table | one less resource and IAM surface; needs Terraform ≥ 1.10 (`terraform/*/versions.tf`) |
| 4 | **CI identity** | GitHub OIDC, three roles: `dev-ci` (admin **inside** a permissions boundary), `ci-plan` (ReadOnlyAccess, any PR), `ci-shared` (scoped ECR + own state key) | static access keys · one god role | no long-lived secrets; the boundary's deny walls (env tag, foreign state, CI identity, boundary self-propagation, budgets, shared ECR) cap what "admin" means — `terraform/bootstrap/environments.tf` |
| 5 | **Pod → AWS auth** | EKS Pod Identity everywhere (app, collector, cloudwatch-agent) | IRSA · node roles · static keys | agent is built into Auto Mode, roles are cluster-portable, one `pod_trust` document; IRSA is the answer only off Auto Mode/Fargate |
| 6 | **Compute mode** | pure EKS Auto Mode, `general-purpose` pool only | managed node groups · Fargate | AWS owns CNI/CSI/LB-controller/Karpenter and Ingress→ALB just works, for a per-instance fee; the template's tenant node group was dropped — no second tenant here, and the first non-Auto node drags four classic add-ons back in (`terraform/modules/stack/eks.tf`) |
| 7 | **Tracing backend** | ADOT collector → X-Ray | SigNoz (named in the prompt) · Jaeger in-cluster | X-Ray is template-proven, adds **zero stateful in-cluster components**, and accepts the Rust SDK's W3C random trace IDs natively (GA Oct 2023; collector pinned v0.49.0); SigNoz means running a database to demo a trace — `deploy/cluster/otel-collector.yaml` |
| 8 | **Redis topology** | ElastiCache Redis 7.1, cluster-mode **disabled**, 1 × `cache.t4g.micro` | cluster-mode enabled · self-hosted | app constraint, not preference: bb8-redis's non-cluster client (no MOVED/ASK) writes to the primary; `num_cache_clusters` is the single HA knob (>1 flips failover+multi-AZ) — `terraform/modules/stack/elasticache.tf` (PR #6) |
| 9 | **Redis security** | TLS in-transit + at-rest + 32-char AUTH token; SG admits only the EKS fleet on 6379 | plaintext inside the VPC | app compiled in rustls for exactly this (`rediss://`); accepted trade: token readable in TF state — and readable not just by appliers: the `ci-plan` role (ReadOnlyAccess, trusted by any PR of this repo) can read the secret-bearing dev state from any collaborator branch, so the compensating control is repo membership + the fork guard, not IAM walls; prod answer is the rotation Lambda (deferred) |
| 10 | **Config delivery** | the **whole `config.yml` is one Secrets Manager secret**, CSI-mounted as a file; app runs `-f /mnt/secrets-store/config.yml` | env vars · ConfigMap + secret merge | the app reads exactly one YAML and the redis URL embeds the token, so file-mount keeps k8s as dumb plumbing; rotation lands on pod restart (app reads once at boot) — `deploy/services/app.yaml` |
| 11 | **App deploy tool** | `helm upgrade --install --atomic` per roster entry, from CI | ArgoCD/Flux · Terraform `helm_release` | one writer per API (Terraform speaks only AWS) and clean destroys; GitOps is the at-scale successor — `.github/workflows/ci.yml` deploy job |
| 12 | **Roster convention** | filename = service = release = ServiceAccount; `scripts/roster.sh` is the one parser | per-service workflow edits | service #2 is one values file in `deploy/services/` plus a Dockerfile/build mapping — both build loops currently build the single root Dockerfile, so a distinct binary needs a per-service build convention too; the convention is load-bearing (Pod Identity associations name the SA) |
| 13 | **Image** | single-arch linux/amd64, musl-static binary on digest-pinned `chainguard/static` (nonroot, CA bundle, no shell) | multi-arch · distroless-cc + glibc | matches amd64 CI runners; the cost is a `kubernetes.io/arch: amd64` nodeSelector because the Auto Mode pool is mixed-arch (`deploy/services/app.yaml`) |
| 14 | **Deploy gate** | `scripts/smoke.sh cloud`: healthz + greeting through the ALB + **counter monotonicity** (the ElastiCache TLS+AUTH round trip) | rollout-status-only | behavior through the real edge, not a liveness ping; no version assert yet (deferred with `service.version`) |
| 15 | **Probes** | liveness = readiness = `/healthz` (no dependencies); `/` returns 500 on Redis failure | readiness on `/` | readiness-on-`/` evicts *every* pod on a Redis blip and converts partial degradation into total outage; a 500 on `/` is the honest signal — `src/routes.rs` |
| 16 | **Releases** | hand-rolled semver from lint-verified PR titles; tag + ECR alias after the smoke-gated deploy | release-please · semantic-release | ~30 auditable lines and zero third-party actions in a `contents: write` workflow; a release means "this version is live and smoke-verified" |
| 17 | **Environment model** | dev continuously deployed from `main`; every other env deployed by `promote.yml` (build once, promote the SHA dev smoked) behind a GitHub Environment approval — cluster-per-env, own keys + non-overlapping CIDRs | all envs continuously deployed · namespace-per-env in one cluster | each *running* env costs its own NAT + control plane + nodes (~$120+/mo), so envs stay opt-in: a bootstrap tfvars entry + a GitHub Environment, not a refactor. Namespace-per-env was rejected outright — soft isolation on a shared control plane and kernel |
| 18 | **Node capacity** | spot-first: a weight-100 Auto Mode NodePool (`deploy/cluster/spot-nodepool.yaml`), on-demand `general-purpose` as the fallback | all on-demand · one mixed `["spot","on-demand"]` pool | ~70% node cost for a 2-min reclaim notice, which the roster already absorbs (2 replicas + PDB + spread, none of it added for spot). Two pools keep capacity-type attribution readable; a single mixed pool lets Karpenter prefer spot itself but blurs that. Revert = delete the manifest, and Karpenter consolidates back onto on-demand |
